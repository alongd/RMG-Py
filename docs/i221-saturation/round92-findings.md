# Round 92 — the third reaction shape, and four ways the gate failed open

Branch `i221-saturation-no-atomtype`, base `5d7d86738`, on plasma head `98d465d3b`.
Probe: `docs/i221-saturation/probes/round92_conversion_probe.py`. Logs: `logs/round92-*`.

Every finding in the review reproduced. **10 of 10 at `5d7d86738`, 4 of 4 controls holding;
0 of 10 after, same 4 controls still holding.** The review was right on every count, including the
two it called fail-open. One framing detail in MEDIUM 4 is wrong in a way that matters for where
the fix goes, and §5 makes that case.

## 1. The HIGH — it is the round-89 defect, one shape over

`KineticsLibrary.get_library_reactions` builds three reaction shapes. Round 89 attached the
authoring `Entry` to the two `LibraryReaction` ones and never looked at the third. Reproduced
end-to-end through `add_seed_mechanism_to_core()`, against the real `Cation_R_Recombination`
manifest on disk:

```
before_conversion_authorship = ['Cation_R_Recombination']
BEFORE_CONVERSION            = REFUSED_FROM_DISK
after_conversion_authorship  = []
after_conversion_entry       = None
ADMITTED_TO_CORE             = True
```

and identically through `add_reaction_library_to_edge()`.

**Repair.** `library.py` now attaches the entry to the template shape as well, and both conversion
sites carry it across (`entry=getattr(rxn, "entry", None)`). Three lines of substance. The entry is
the right carrier because the entry's `long_desc` is the same text the family was parsed out of one
statement earlier — the conversion was discarding a value it had in its hand and had just printed.

`TemplateReaction.__init__` takes no `entry` parameter, so `library.py` assigns the attribute after
construction rather than passing it. `rmgpy/data/kinetics/family.py` is outside this round's gates;
a constructor parameter there would be tidier and is left for whoever opens that file next.

**The hazard is honoured.** After the conversion `reaction.family` still holds the library label,
asserted by a probe control and by
`TestTheThirdShapeSurvivesTheConversion::test_the_conversion_still_writes_the_library_label_into_the_family_slot`,
which drives a conversion that is allowed to complete and then reads the slot. Nothing in this
round touches `LibraryReaction.__init__`, so `electron_placement.py`'s
`FAMILY_ELECTRON_PLACEMENT` lookup is unchanged.

## 2. The census the review asked for

**How I know it is complete: I derived it from the readers, not from a grep of constructors, then
cross-checked against that grep.** The gate is called in exactly four places in the whole engine
(`rmgpy/rmg/model.py:1069, 1612, 1644, 2020` — nothing else in `rmgpy/` calls `check_quarantine`).
Those four functions have eight callers (`model.py` ×6, `pdep.py` ×2). Tracing each caller back to
what produced the reaction it passes gives the list below; the constructor grep then confirms no
production site was missed.

**16 construction sites** of the two wrapper classes exist in `rmgpy/` (11 `LibraryReaction`, 5
`TemplateReaction`, after excluding one class statement and two `__repr__` strings). **Seven can
reach the gate:**

| site | shape | authorship carrier | state |
|---|---|---|---|
| `data/kinetics/library.py:354` | library, auto-generated | `entry` | round 89 |
| `data/kinetics/library.py:373` | **template, auto-generated** | `entry` | **this round** |
| `data/kinetics/library.py:390` | library, ordinary/pdep | `entry` | round 89 |
| `data/kinetics/database.py:494` | library, generated from a library | `entry` | already correct upstream |
| `data/kinetics/family.py:1762` | template, generated by a family | `.family` | correct by construction |
| `rmg/model.py:1745` | **conversion, seed path** | `entry` | **this round** |
| `rmg/model.py:1882` | **conversion, reaction-library path** | `entry` | **this round** |

**Three conversion sites** exist — one reaction rebuilt as another. Two are the ones above. The
third is `chemkin.pyx:2133` in `write_kinetics_entry`, which splits a `MultiArrhenius` into leaves
for output; it drops the entry too, and that is harmless because the objects it makes are written
to a file and never returned to a model.

**The nine construction sites that cannot reach the gate**, and why: seven in `chemkin.pyx` build
reactions while *reading* a Chemkin file, and every caller of `load_chemkin_file` in `rmgpy/` is an
analysis tool (`yaml_rms`, `tools/uncertainty`, `tools/loader`, `tools/diffmodels`) — none builds a
`CoreEdgeReactionModel` or admits anything to a core or edge. `family.py:1306` is internal to
training-set reverse-rate arithmetic. `chemkin.pyx:2133` is the writer above.

**The eighth reader, which is not a construction site:** `pdep.py:934/946` push *net* reactions
from a pressure-dependent network into core and edge. Those objects carry no authorship at all, and
deliberately so — they are derived quantities, not copies of anyone's rate. They are safe because
the network's *inputs* are gated: round 89 put `check_quarantine` on
`add_reaction_to_unimolecular_networks`, so a quarantined path reaction cannot enter a network for
a net reaction to be derived from. That is the whole reason the fourth gate had to exist, and it is
what makes the census closeable rather than infinite.

## 3. The four MEDIUM

**1. Cache staleness and the TOCTOU fail-open.** `_DISK_QUARANTINE_CACHE` now stores
`(signature, answer)` and re-takes the signature — `(mtime_ns, size, inode)` of the manifest, plus
whether the family directory exists — on every lookup, two `os.stat` calls. A manifest added,
edited or removed mid-run is seen, in both directions. Separately, when the signature says the file
is there and the loader finds it gone, that is no longer `(None, True)`: it is `(None, False)`,
logged by name, and **not cached**, because the next call may find the file back.
`load_family_quarantine` catches the `FileNotFoundError` rather than killing a run over a
concurrent database edit. Three tests, one per direction plus the race.

**2. Family labels are not paths.** `_family_directory()` refuses any label that is absolute, that
carries a path separator, or that is `.`/`..`, and then requires the *resolved real path* to sit
under the resolved real families root — the second check is what catches a single-component label
whose directory is a symlink out of the tree, which syntax alone cannot see. A refused label is
logged at ERROR once per label and makes the rate's authorship unresolvable rather than silently
absent. Shown refusing an absolute label, a `..` label and a symlink; shown still resolving an
ordinary one.

**3. The call-site pin.** Third round running, and the review is right that "either verify what the
name says or rename it". I verified it. `_live_gate_calls()` replaces the call counter and now
refuses three things it used to accept — a call in a statically dead branch, a call at module scope
rather than inside a function, and `something_else.check_quarantine(...)` where the receiver is not
the declared engine module — and, through `_GATE_CALL_SITES`, requires a live call inside **each**
of the four admission functions this engine defines, not one call anywhere in the file. Deleting
three of the four gates is now refused, naming which are missing.

The required list lives beside the checker rather than in the manifest, deliberately: a database
cannot know an engine's internal structure, and a manifest schema change is out of this round's
gates. The side effect is a tripwire — an engine that grows a fifth admission path fails its own
pin until that path is gated, which is the failure I would want.

**The bound is still real and is stated in the docstring rather than claimed away: no static check
proves a call executes.** What is now closed is *coverage*, which is what the field's name implies
and what three rounds of review have been circling.

**4. Silent admission.** `_warn_unanswered`'s suppression now consults disk as well as loaded
families (`_database_has_any_quarantine()`), so a run early enough that nothing is loaded still
warns in a database that carries manifests. Its own bound: the disk half is keyed on the families
directory's signature, so a manifest dropped into an already-existing family directory mid-run is
not noticed by the *suppression* until something re-reads that directory. It can only make a
warning appear or not — never a refusal, which goes through `resolve_quarantine` and re-checks the
manifest's own signature every time.

## 4. The fixture gap is closed where the HIGH lived

`quarantineTest.py:617` still assigns `reaction.entry` by hand, and that is now the *only* fixture
of that shape; it is kept because it exercises a construction the loader does not make, and it is
no longer the coverage for anything. The auto-generated shape is now covered by
`test_the_real_loader_attaches_the_entry_to_the_template_shape`, which calls
`KineticsLibrary.get_library_reactions()` and asserts on what comes back, and by three tests that
drive `add_seed_mechanism_to_core()` and `add_reaction_library_to_edge()` themselves.

## 5. Where I think the review is wrong

MEDIUM 4 says: *"an unloaded family that has a manifest on disk is admitted with no message at
all."* That case is not admitted — it is **refused**. `resolve_quarantine` reads the manifest from
disk precisely so that an unloaded family is still an answerable question; that was round 89's
repair and the probe's `BEFORE_CONVERSION = REFUSED_FROM_DISK` line is it working.

The defect underneath is real and is worth more than the sentence: the silence is in the *other*
case — a family this database does not contain at all — and what should have kept the warning
switched on is **the database's other manifests**, which the suppression never looked at because it
iterated loaded families. So the fix is not "warn about unloaded families with manifests" (they are
already refused) but "stop deciding this database quarantines nothing by asking only the families
that happen to be loaded". That is what shipped, and the distinction is recorded in
`TestTheSuppressionConsultsDiskToo`'s docstring so the next reader does not re-derive it.

## 6. Named, not fixed

- **The conversions still drop `electrons`, `allow_pdep_route` and `elementary_high_p`.** Same two
  sites, same class of defect — fields in hand, discarded on rebuild. `electrons` is the one with
  teeth: `electron_placement.py` reads it, and a converted plasma seed reaction arrives with
  `electrons=0`. No test in this ticket covers what changing it would do to placement or to
  reaction balance, and the round-89 addendum is explicit that guessing there is how argon
  ionisation breaks silently. It needs its own ticket and its own probe.
- **`Cation_R_Recombination`'s manifest prose.** The database's `quarantine.py` describes
  `requiresEngineCallSites` in terms the check did not earn until today, and now under-describes it.
  The RMG-database repository is off-limits this round; the ledger correction belongs there.
- **`TemplateReaction` has no `entry` parameter.** Left as an attribute assignment; `family.py` is
  outside the gates.

## 7. What I could not reach

- **Proof that a gate call executes.** Static analysis cannot do it. Coverage instrumentation on a
  real run could, and would belong in CI rather than in a manifest check.
- **A concurrent-edit race that is not simulated.** Both the probe and the test make the TOCTOU
  window deterministic by deleting the file from inside the existence check. That exercises the
  real code path with real filesystem state, but it is not a genuine two-process race, and I did
  not attempt one.
- **`get_library_reactions`' first shape in a real run.** The "Originally from reaction library:"
  branch is covered by tests and by the probe's controls, but I have not seen it fire in a
  production RMG run in this campaign; all three shapes are exercised here from constructed
  libraries.
- **Whether any shipped database actually contains a hostile or malformed `family:` line.** The
  path-escape repair is a hardening, not a response to a sighting. I did not survey the databases.
